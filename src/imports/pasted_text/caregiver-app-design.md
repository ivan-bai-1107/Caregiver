请为一个完整的数字医疗护理辅助产品设计一整套界面，产品名称为“医疗照顾者客户端系统”。该产品包含两个部分：

1. 前台移动端 App（面向医疗照顾者）
2. 后台 Web 管理系统（面向管理员）

这是一个“护理辅助系统”，不是医院诊断系统，也不是娱乐社交产品。产品的核心目标是帮助医疗照顾者（患者家属、护工等）完成以下工作：
- 管理多个患者
- 记录护理信息
- 创建和管理护理任务
- 查看健康指标趋势图
- 通过 AI 助手完成问答、护理记录预填写、任务预填写、表单预填写
- 学习护理知识
- 进行轻量经验交流
- 在后台进行知识内容管理、社区治理、Prompt 模板管理和 AI 日志查看

系统强调：
- 辅助而非替代
- 连续观察而非单次操作
- 结构化记录而非零散输入
- 合规交流而非开放式医疗讨论

====================
一、整体设计风格要求
====================

请整体采用“现代、简洁、专业、可信、温和”的设计风格，突出医疗辅助产品的秩序感和安全感。

前台 App 风格要求：
- 移动端界面
- 浅色背景为主
- 配色柔和、清爽、不过度鲜艳
- 强调卡片式分组、状态标签、表单可读性
- 适合中青年照顾者和中老年家属使用
- 重要信息清晰前置
- 不要有强社交产品感、不要娱乐化
- AI 页面不要做成普通聊天产品，要更像“智能任务理解与辅助入口”

后台 Web 管理系统风格要求：
- Web 控制台风格
- 左侧菜单 + 顶部栏 + 主内容区域
- 简洁、专业、管理化、表格化
- 适合内容管理和审核场景
- 不需要做成复杂 BI 平台

二、产品结构与导航要求
====================

前台 App 底部导航固定为 5 个一级入口：
1. 首页
2. 患者
3. 记录
4. 学习/社区
5. 我的

其中“学习/社区”页面内可用顶部 Tab 切换：

- 经验交流

患者详情页是整个前台系统的核心页面，应作为患者护理的总控台，整合以下内容：
- 患者基本信息
- 护理记录
- 护理任务
- 健康趋势入口

AI 功能不再拆成多个孤立页面，而是统一进入“AI 助手页”。用户在 AI 助手页中输入自然语言，系统自动识别意图并完成：
- 护理问答
- 护理记录预填写
- 护理任务预填写
- 表单预填写

AI 助手返回的结果如果是结构化草稿，则进入“AI 结果确认页”，由用户确认后再保存。

====================
八、关键交互流程要求
====================

请在原型中体现以下关键流程：

1. 注册流程
登录页 -> 注册页 -> 输入邮箱 -> 发送验证码 -> 输入验证码 -> 输入用户名和两次密码 -> 注册成功 -> 返回登录

2. AI 记录生成流程
首页或患者详情 -> 打开 AI 助手 -> 输入“帮我记录今天上午血压120/80” -> 系统识别为护理记录 -> 返回草稿 -> 进入 AI 结果确认页 -> 用户确认 -> 保存成功 -> 返回记录列表/患者详情

3. AI 创建任务流程
患者详情或任务页 -> 打开 AI 助手 -> 输入“帮我创建一个每天早上8点测血压的任务” -> 系统识别为任务 -> 返回任务草稿 -> 确认 -> 保存 -> 返回任务列表

4. 健康趋势分析流程
